# ADC 内部温度采集 —— 上台汇报稿（约 2 分半）

## 开场

各位老师好，我汇报的是 ADC 内部温度采集任务。这个任务是在上次串口控制工程的基础上做的，一共六件事：采集芯片内部温度并做标定、左转向灯呼吸、右转向灯彩虹、OLED 大字与中文显示、串口中文提示。

## 一、温度采集

STM32 芯片内部自带一个温度传感器，它固定接在 ADC1 的通道 16 上，用之前必须先打开 TSVREFE 这个使能位，不然读出来永远是 0，这是第一个容易踩的坑。

我每 2 秒采一次，一次连读 8 个值，**先丢掉切换通道后的第一次转换**，再从剩下的值里去掉最大和最小各一个再取平均，这样偶发的野点拉不偏结果。采样时间给到 239.5 个周期，也就是 20 微秒左右，满足手册要求的 17.1 微秒下限。

换算按任务书给的公式：V25 减 Vsense，除以 4.3 毫伏每摄氏度，再加 25，其中 V25 取 1.43 伏。另外我用通道 17 的内部 1.2 伏基准反推板上真实的 VDDA，电压和温度都用实测值去换算，比直接假定 3.3 伏准确。

## 二、温度标定

芯片跑起来会自己发热，读出来会比室温高几度。工程支持单点标定：在串口里敲大写 K 加当前室温，回车就把偏移量写进内部 Flash，掉电不丢；敲 Z 可以清除标定，回到原始公式。

## 三、左转向灯呼吸

左转向灯是板子左上角那颗四脚 RGB 灯珠，三路分别接在 PG0、PG1、PG2 上。这里有个硬件限制：这组引脚在 F103 上**没有连到任何定时器通道**，出不了硬件 PWM。所以我用 TIM2 做 20 千赫兹的定时中断，在中断里自己计数、自己写引脚，等效出一个 200 赫兹、100 级亮度的软件 PWM，每 20 毫秒调一次占空比，一亮一暗一个来回大约 2 秒，呼吸感比较自然。按下 KEY2 进入呼吸，再按一次退出。

## 四、右转向灯彩虹

右转向灯是右上角那颗 RGB 灯珠，接在 PE2、PE3、PE4 上。打开以后以 500 毫秒为半周期闪烁，每闪一次换一个颜色，按红、黄、绿、青、蓝、紫六色轮转，就是彩虹的效果。两盏灯亮灭的时候会一起带动旁边的板载小灯，车灯负责远处可见、小灯负责近处看状态。

## 五、OLED 显示

屏是 0.86 寸、128 乘 32 的 SSD1306，用软件 I2C 驱动。一开始四行 8x8 小字把 32 个像素顶满了，很挤、看不清，所以我做了两点改动：

一是**放大字**——把 8x8 字模按每行复制一遍、每列复制一遍放大成 16x16，温度用大字单独占上半屏，下面分栏显示 ADC 原始值和换算电压，最后一行显示设备状态。

二是**小数点单独处理**——8x8 字模里的句点只有 2x2 个像素，放大以后也才 4x4，在这块小屏上基本看不见，所以我绕开字模，直接画一个 6x6 的实心方块，一眼就能看出是小数点。

汉字用的是自己生成的 16x16 点阵字库，收录界面用到的 60 个汉字，按 GBK 编码查表，查不到就画一个空心方框，方便一眼看出缺字。

## 六、串口中文

界面提示和串口提示都改成了中文，汉字按 GBK 编码发送，一个汉字两个字节。**要注意串口助手的接收编码默认是 UTF-8，得改成 GBK 或者 ANSI**，不然看到的是乱码。任务书要求的那几行英文上报格式我原样保留，中文只是追加在后面，不影响验收。

## 温度偏高是怎么修的（重点）

上板以后，室温下屏上显示 98 度，看着像芯片在发烧。我是这么一步步定位的：

**第一步，先判断是真高温还是固定偏差。** 看开机瞬间的第一次读数，上电才一秒就已经 96 度了。芯片有热质量，不可能一秒之内从室温冲到 96 度，所以这里面绝大部分是固定偏差，后面从 96 度慢慢爬到 98 度的那两三度才是真实的芯片自热。

**第二步，把公式和基准逐个排除。** 公式是任务书给的，没错；VDDA 用内部 1.2 伏基准反推过，实测在合理区间内。这一路也是准的。

**第三步，直接看原始值。** 把 ADC 的原始读数和换算出来的电压一起打出来对比，发现换算出的 Vsense **比正常值低了大约 276 毫伏**。按 4.3 毫伏每摄氏度折算，276 毫伏差不多就是 60 多度的误差——98 度这个数这才对上了。

**第四步，找到根因。** 问题出在驱动上：ADC 切换通道之后，采样保持电容还没稳定，第一次转换的结果会偏低。旧驱动没有把这一次丢掉，等于把一个偏低的电压直接喂给了公式。

**第五步，重写驱动。** 切通道后丢掉第一次转换、8 次采样去掉最大最小各取平均、采样时间给到 239.5 个周期。改完 98 度就消失了，剩下 5 度左右是这颗片子真实的芯片自热，最后用单点标定抹平。

这里我想说的是：**98 度不是传感器坏了，是采样时序的问题**，仪器读数离谱的时候，先怀疑自己的采样流程，比怀疑硬件更有效率。

## 还有一个坑：标定值会被下载擦掉

Keil 默认是整片擦除，会把 Flash 最后一页的数据一起擦掉，标定值就丢了。我在工程的下载设置里把下载范围限制到 0x0807F800 之前，只擦程序区，数据页保留。所以**重新编译下载以后，标定值、下发文本、设备状态都还在**，不用重做。

## 验证

工程用 Keil 编译，**0 错误 0 警告**。上板以后把每一项都单独试过：三颗按键、左右转向灯、OLED 两个显示页、串口中文与英文上报、掉电恢复，全部正常；OLED 上显示的数据和串口打印的完全一致。

固件还做了上电自检：屏有没有应答、用的是哪个地址，开机横幅会直接打在串口上，屏不亮的时候一眼就能看出是接线问题还是驱动问题。

## 备问要点（老师追问时用）

| 可能的问题 | 回答要点 |
|---|---|
| 内部温度传感器用哪个通道？ | ADC1 的通道 16（ADC_Channel_16）；内部通道只有 ADC1 能选，且必须置 ADC_CR2 的 TSVREFE 位，否则读回恒 0 |
| 采样时间为什么给那么长？ | 手册要求内部温度传感器采样 ≥ 17.1μs；ADCCLK=12MHz 时选 239.5 周期 ≈ 20μs |
| 温度公式？ | 温度 = (V25 − Vsense) / 4.3mV + 25，V25=1.43V；负温度系数，温度越高电压越低 |
| 为什么采样要丢第一次、还去极值？ | 切换通道后第一次转换的采样保持电容还没稳定，结果偏低（实测偏低约 276mV）；8 次里去掉最大最小各一个再平均，抑制偶发野点 |
| 98℃ 是怎么来的？ | 不是传感器坏，也不是 V25 偏差，是**旧驱动没丢切通道后的第一次转换**，Vsense 偏低 276mV ≈ 63℃，重写驱动后消失 |
| 现在还剩几度偏差？ | 剩下约 5℃ 是芯片真实自热（72MHz 全速跑的 die 温度天生高于环境），用 `K<室温>` 单点标定抹平 |
| 标定值存哪？掉电丢吗？ | 存内部 Flash 数据页 0x0807F800，和设备状态、下发文本放在同一条记录里，带魔数 + 累加和校验；掉电不丢 |
| 下载会不会把标定擦掉？ | 会——所以把 Keil 下载范围限制到 `0x0807F800` 之前（工程里是 `-FL07F800`），只擦程序区 |
| VDDA 反推有什么用？ | 通道 17 是内部 1.20V 基准 Vrefint，用它反推真实 VDDA；合理窗口放宽到 1800~4600mV，避免供电稍微偏离就被当坏点退回 3.3V |
| 左转向灯为什么用软件 PWM？ | 左灯珠是 PG0/PG1/PG2，这组脚在 F103 上没有定时器通道，硬件 PWM 出不来；用 TIM2 20kHz 中断 + 100 级计数 = 200Hz 软件 PWM |
| 20kHz 中断会不会拖慢系统？ | 约 3% CPU；只在电平真的变化时才写 GPIO，退出呼吸模式立刻关定时器，零开销 |
| 右转向灯的彩虹怎么做的？ | 右灯珠接在 PE2、PE3、PE4 三路；闪烁服务每 500ms 翻转一次亮灭，亮的时候按红→黄→绿→青→蓝→紫 取下一个颜色，六色走一圈再回到红 |
| 左右灯同时打开会互相干扰吗？ | 不会。呼吸模式下沉呼吸模块独占左灯珠，转向灯闪烁服务会跳过左灯，保证同一组引脚只有一个模块在写 |
| OLED 大字怎么来的？ | 没有做新字模，把 8x8 字模按「行复制、列复制」放大 2 倍得到 16x16，纵向跨相邻两页 |
| 小数点为什么单独画？ | 8x8 字模里句点只有 2x2，放大也才 4x4，在 0.86 寸屏上几乎看不见；大字模式下直接画 6x6 实心方块 |
| 汉字字库怎么来的？ | 自己生成，宋体 16 像素无抗锯齿取模，收录 60 个常用汉字，按 GBK 双字节编码线性查表，查不到画空心方框 |
| 串口中文为什么我这里是乱码？ | 串口助手接收编码默认 UTF-8，改成 GBK 或 ANSI 即可；固件按 GBK 逐字节发送，一个汉字 2 字节 |
| 按键怎么消抖？ | 10ms 扫描周期 + 20ms 消抖确认，按下沿报一次单击事件；KEY1 切显示页、KEY2 呼吸灯、KEY3 立即采样 |

## 上机演示步骤（照做即可）

1. 烧录 `ADC温度修复版_直接烧录.hex`，打开串口助手（115200-8-N-1，**接收编码设为 GBK**）。
2. 看开机横幅：第一行 `=== AdcTemp Full (115200-8-N-1) ===`，下面跟几行中文说明（本工程 = 串口控制 + ADC 内部温度采集），最后一行 `Info : 系统启动完成`；紧接着是屏自检结果 `OLED : ack ok, slave addr 0x78` —— 说明供电和接线都正常。
3. 等 2 秒自动上报一次，数一下：`Current ADC_Value is ...`、`Current Voltage is ...`、`Current Temperature is ...`、`Current VDDA is 31xx mV` —— VDDA 落在 3.1V 左右说明换算基准是准的。
4. OLED 温度页上半屏大字显示当前温度，下面分栏显示 ADC 原始值和电压。
5. 串口发送框输入 `K29` 再回车（29 换成你手机天气里的实时室温），会打印标定结果，温度立刻对齐室温。
6. 按 KEY2：左上角大灯开始**呼吸**（由暗到亮再回暗，约 2 秒一个来回）。再按 KEY2 退出。
7. 串口发 `L1`：左上角大灯进入呼吸 + 左侧小灯闪烁；发 `L0` 关。发 `R1`：右上角大灯**彩虹闪烁**，六色轮转；发 `R0` 关。
8. 发 `Z` 回车可以清除标定，回到原始公式的结果。
9. 按 KEY1 切到文本页，发 `T你好` 回车，屏上下半屏会显示中文提示。

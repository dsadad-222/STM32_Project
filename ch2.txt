1.4、芯片内部有什么

 STM32 芯片是已经封装好的成品，主要由内核和片上外设组成。若与电脑类比，内核与外设就如同电脑

上的 CPU 与主板、内存、显卡、硬盘的关系。STM32F103 采用的是 Cortex-M3 内核，内核即 CPU，
由 ARM 公司设计。ARM 公司并不生产芯片，而是出售其芯片技术授权。芯片生产厂商(SOC)如 ST、TI、

Freescale，负责在内核之外设计部件并生产整个芯片，这些内核之外的部件被称为核外外设或片上外

设。如 GPIO、USART（串口）、I2C、SPI 等都叫做片上外设。

 
 
1.5、系统结构框图

图片截图于参考手册（2存储器和总线架构P25页）

ICode总线：即指令总线。我们写好的程序编译之后都是一条条指令，存放在 FLASH 中，内核要读取这

些指令来执行程序就必须通过 ICode 总线，它几乎每时每刻都需要被使用，它是专门用来取指的。

DCode总线：即数据总线。我们在写程序的时候，数据有常量和变量两种，常量就是固定不变的，用 C 

语言中的 const 关键字修饰，是放到内部的 FLASH 当中的，变量是可变的，不管是全局变量还是局部变

量都放在内部的SRAM。因为数据可以被 Dcode 总线和 DMA 总线访问，所以为了避免访问冲突，在取

数的时候需要经过一个总线矩阵来仲裁，决定哪个总线在取数。

System总线：系统总线主要是访问外设的寄存器，我们通常说的寄存器编程，即读写寄存器都是通过这

根系统总线来完成的。

 
DMA总线：DMA 总线也主要是用来传输数据，这个数据可以是在某个外设的数据寄存器，可以在

SRAM，可以在内部的 FLASH。因为数据可以被 Dcode 总线和 DMA 总线访问，所以为了避免访问冲

突，在取数的时候需要经过一个总线矩阵来仲裁，决定哪个总线在取数。

内部的闪存存储器：内部的闪存存储器即 FLASH，我们编写好的程序就放在这个地方。内核通过 ICode 

总线来取里面的指令。

内部的SRAM：内部的 SRAM，即我们通常说的 RAM，程序的变量，堆栈等的开销都是基于内部的

SRAM。内核通过 DCode 总线来访问它。

FSMC：FSMC 的英文全称是 Flexible static memory controller，叫灵活的静态的存储器控制器，是 

STM32F10xx 中一个很有特色的外设，通过 FSMC，我们可以扩展内存，如外部的SRAM，NANDFLASH 
和 NORFLASH。但有一点我们要注意的是，FSMC 只能扩展静态的

内存，即名称里面的 S：static，不能是动态的内存，比如 SDRAM 就不能扩展。

AHB到APB总线桥：从 AHB 总线延伸出来的两条 APB2 和 APB1 总线，上面挂载着 STM32 各种各样的

特色外设。我们经常说的 GPIO、串口、I2C、SPI 这些外设就挂载在这两条总线上，这个是我们学习 

STM32 的重点，就是要学会编程这些外设去驱动外部的各种设备。

1.7、寄存器映射

在存储器 Block2 这块区域，设计的是片上外设，它们以四个字节为一个单元，共 32bit，每一个单元对

应不同的功能，当我们控制这些单元时就可以驱动外设工作。我们可以找到每个单元的起始地址，然后

通过 C 语言指针的操作方式来访问这些单元，如果每次都是通过这种地址的方式来访问，不仅不好记忆

还容易出错，这时我们可以根据每个单元功能的不同，以功能为名给这个内存单元取一个别名，这个别

名就是我们经常说的寄存器，这个给已经分配好地址的有特定功能的内存单元取别名的过程就叫寄存器

映射。

 
在数据手册P28页可以看到各个外设的寄存器地址，或者参考手册的P28页也可以查到。通过寄存器可以

操作单片机的各个外设。

电源：   （VBAT）、（VDD、VSS）、（VDDA、VSSA）、（VREF+、VREF-）等等;

3、程序下载

3.1、仿真器下载（JTAG/SWD）

核心是通过专用的调试接口（JTAG或SWD），直接读写芯片内部的Flash存储器。

所需硬件：一般包括，ST-Link、J-Link、DAP-Link。

优点：支持程序下载，在线仿真调试、单步执行、变量查看等；数据传输速率高；IDE（Keil、IAR等）中

可以一键下载无需手动调整跳线。

缺点：需要额外的工具，同时会占用几个固定的IO引脚用于调试接口。

 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
3.2、串口下载（ISP方式）

ISP为在系统编程。核心是利用芯片出厂时预置在“系统存储器”中的一段BootLoader程序，通过串口
UART接收数据并写入Flash存储器。

所需硬件工具：所需USB转TTL串口模块或者开发板自带的USB转串口电路。

优点：无需购买额外的调试器，一根串口线即可；适合量产和现场升级。

缺点：只支持下载程序不能调试；需要手动切换BOOT0引脚的电平状态，让芯片从系统存储器启动，下

载完成后还需切回，才能运行用户程序，不过一般设计“一键下载电路”简化了这个步骤。

常用软件工具：STM32CubeProgrammer（官方推荐的首选工具）、FlyMcu、mcuisp(第三方的ISP

下载工具)。

3.2.1、常规手动下载模式

STM32的ISP下载通常只支持USART1（USB转TTL模块与USART1进行交叉连接），其次需要将STM32进

入ISP模式（就是将BOOT0引脚拉高、BOOT1引脚拉低），配置好后复位或重新上电芯片，则会从“系统

存储器”启动，运行内部的BootLoader，等待通过串口接收程序。

3.2.2、一键ISP下载模式

许多开发板会通过USB转串口芯片（如CH340）的DTR和RTS引脚，配合额外电路，连接到STM32的

BOOT0和NRST（复位）引脚。上位机软件（如FlyMcu）通过控制这两个引脚的电平，可以自动完成进

入ISP模式和复位操作，实现点一下按钮就完成下载，无需手动跳线，非常方便。

以FlyMCU下载为例。FlyMCU软件可以通过串口将编译好的程序代码（hex文件）下载到目标MCU芯片

中。

步骤1：使用数据线可以通过开发板的TPYE-C接口烧录程序。使用Type-C数据线连接电脑后，可以在设

备管理器：端口查看对应设备的串口号。

 
 
 
步骤2：打开FlyMCU软件，其中BootLoader选项配置为：DTR的低电平复位，RTS高电平复位进

BootLoader。

步骤3：下载程序成功后，按一下开发板的RESET按键，观察开发板现象是否正常。

4、GPIO寄存器

我们已经知道单片机是通过地址来范访问寄存器的，那有哪些寄存器呢？

STM32F103相关GPIO寄存器可以参考官方的参考手册P113页（8通用和复用功能I/O）。寄存器地址可
以查看参考手册P28页。

在芯片参考手册中看到CRH或CRL寄存器，可以把引脚配置为上拉/下拉输入模式，但是并没有说明如何

区分上拉还是下拉？

其实，当引脚配置为上拉/下拉输入模式后，是通过BSRR寄存器和BRR寄存器来确认上下拉的，

BSRR寄存器对对应的位-置位则是上拉，BRR寄存器对对应的位清零则是下拉。
